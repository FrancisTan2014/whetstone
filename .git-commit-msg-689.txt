feat(notes-review): retry-safe direct card creation command (#689)

Add `POST /api/notes/review/direct-cards`: turn an authored question/answer
pair into one manual standalone note + one contains-linked prompt + one active
shared review card (retention 0.90, due now) + one owner-scoped creation
receipt, all in a single transaction and writing no review event.

Idempotency is keyed by (user_id, submission_id) via an onConflictDoNothing
receipt insert that serializes concurrent/sequential retries: an identical
replay returns the original result, a changed-payload replay is a conflict
(409), and a replay whose note was deleted is gone (410). The receipt stores
plain-text ids with no FK, so it sits outside deleteNoteInTx's cascade as a
non-resurrecting tombstone. All readable text is derived server-side; a blank
question/answer/Success check is rejected before any write.

Reuses the #686 reveal-column policy (extracted to noteGradingColumns) and the
single note-prompt writer (insertNotePromptInTx, which
insertCurrentNotePromptInTx now delegates to).
